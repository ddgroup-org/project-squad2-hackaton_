Contexto e Objetivo

Por que este documento existe

Antes de configurar qualquer coisa via Claude na org do hackathon, o time precisa de um desenho técnico único, para que os diferentes prompts/demandas executados ao longo do dia não gerem retrabalho ou decisões conflitantes entre si. Este documento é essa referência única.

Consolidar o diagrama de objetos, o Data Mapping campo a campo, o modelo de segurança e as automações previstas para a implementação Sales Cloud + Service Cloud do cliente simulado Cromatta Química, e orientar como cada parte será construída via prompts do Claude nas próximas demandas.

Seção 2

Diagrama de Objetos

Fluxo principal de dados, do primeiro contato com o lead até o acompanhamento pós-venda/laboratório.

Leitura do diagrama

  • Lead → Account/Contact/Opportunity: conversão padrão do Salesforce, associando a oportunidade à linha de produto de interesse.
  • Opportunity → Product2/PricebookEntry: via OpportunityLineItem, para os dois caminhos comerciais (produto existente ou a desenvolver).
  • Opportunity → Amostra__c: cada amostra enviada ao cliente é um registro relacionado à oportunidade, não um campo solto — permite múltiplas tentativas rastreadas.
  • Amostra__c → Case: quando uma amostra é reprovada, um Case é criado e roteado à fila do laboratório.

Seção 4

Security Model

Status na data deste documento: ESPECIFICADO, NÃO IMPLEMENTADO. Verificado via MCP (run_soql_query em PermissionSet/EntityDefinition) e via retrieve de PermissionSet/SharingRules direto da org: nenhum Permission Set, Sharing Rule ou objeto "Amostra" relacionado a este projeto existe hoje na org do hackathon. A "Tarefa 02" referenciada no contexto desta demanda ainda não foi executada — o que segue é o design a ser implementado, não uma descrição do que já existe.

Organization-Wide Default (OWD)

ObjetoOWDEfeito
AccountPublic Read OnlyTodo vendedor lê qualquer conta; só o owner edita
OpportunityPublic Read OnlyTodo vendedor lê qualquer oportunidade; só o owner edita
CasePublic Read OnlyLeitura geral; edição pelo owner (vendedor ou químico da fila)
Lead / Product2 / Amostra__cPadrão da plataformaSem requisito de restrição adicional do cliente

Public Read Only nesses três objetos já entrega "lê tudo, edita só o próprio" nativamente (owner mantém edição) — sem necessidade de sharing rules adicionais para esse requisito específico do cliente.

Permission Sets

Vendedor

CRUD em Lead/Account/Opportunity/Case que possui; leitura nos demais; sem acesso à aprovação de preço.

Químico / Laboratório

Acesso à fila de Case "Laboratório"; CRUD em Case; leitura em Opportunity/Account relacionados.

Gestor

Acesso total; aprovador do fluxo de preço/desconto; visão de todos os relatórios e dashboards.

Automações Previstas

Ordem de preferência sempre declarativa (config → Flow → Approval Process → Apex/LWC só se necessário), conforme architecture.md.

AutomaçãoMecanismoComportamento esperado
Aprovação de preço/descontoApproval ProcessToda alteração de preço-base do produto ou desconto por volume na Opportunity é submetida para aprovação do Gestor antes de valer.
Fila do laboratórioRecord-Triggered Flow + QueueAo registrar uma amostra reprovada, cria um Case (RT Amostra/Teste), atribui à Queue "Laboratório" e roteia ao químico responsável pela linha de produto.
Alerta de concentração de receitaScheduled Flow + Email AlertCalcula periodicamente a % de receita por vendedor/cliente; notifica o Gestor ao ultrapassar o limite (referência: 60% já é tratado como alarmante pelo cliente — limite exato é pendência a confirmar).
Prazos de resposta (SLA)Entitlement Process + MilestonesAcompanha os prazos informados pelo cliente: ~15 dias para produção de amostra, cobrança a cada 10 dias úteis sem retorno, ~5 dias úteis para retorno de amostra reprovada. Depende de confirmação de licença Entitlement Management na org.
